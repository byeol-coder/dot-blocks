# DOT BLOCKS Blind-first QA

## UI/UX 세련화 패스 — 작업 보고 (UI 작업 표준 원칙 기준)

- **재사용한 기존 토큰**: `--accent`, `--accent2`, `--ok`, `--danger`, `--muted` 그대로 유지
- **신규 공통 토큰**: `--cta-1`/`--cta-2`/`--cta-glow`(3곳에서 드리프트되던 CTA 그라데이션 통일), `--panel-deep`/`--panel-deep-2`/`--line-blue`/`--line-blue-soft`(반복되던 패널·보더 블루 통일), `--ease`/`--ease-out`(트랜지션 타이밍)
- **아이콘**: 유니코드 글리프(Ⅱ, ★) 2건을 발견해 기존 인라인 SVG 아이콘 시스템과 통일된 스타일로 교체 (Tabler 스타일 stroke 2px 유지, 신규 임의 SVG 없음)
- **중복 제거**: 동일 의도의 CTA 그라데이션 3벌(인트로 시작 버튼/플레이 헤더 로고/오버레이 확인 버튼)을 토큰 1벌로 통합
- **접근성 검증 결과**:
  - 색상 대비: 화이트 텍스트 on CTA 그라데이션 시작색 2.91:1 → `#0a86dd` 조정 후 3.84:1 (WCAG AA 큰글자 기준 3:1 충족)
  - 터치 타깃: `.btn`(39→44px), 홈/메뉴 버튼(40→44px), 드로어 닫기(40→44px), 플레이 컨트롤바 버튼(40→44px) 모두 44px 기준 충족. `max-height:720px and min-width:641px` 압축 쿼리(34px)는 터치가 아닌 데스크톱/노트북 좁은-세로 창 전용으로 판단해 기존 압축 규칙 유지
  - `prefers-reduced-motion`: 신규 트랜지션/애니메이션 전체를 포괄하도록 리셋 규칙 확장, 코드 검증 통과
  - 키보드 포커스: 기존 `body.kbd` 포커스 링 규칙 변경 없음
- **모션**: 신규 진입 애니메이션(인트로/플레이/드로어/오버레이)은 전부 `[hidden]` 속성 기반이라 JS 변경 없이 CSS만으로 구현 — 게임 로직 손상 위험 없음
- **코드 검증**: CSS 중괄호 균형(301/301), 인라인 JavaScript·`audio-engine.js`·`tts.js` `node --check` 전부 통과

## 자동/코드 검증 완료

- `index.html` 인라인 JavaScript `node --check` 통과
- `audio-engine.js` `node --check` 통과
- DOM/API 스텁 기반 초기화 및 입력 시뮬레이션 통과
- 낙하 모드 시작, 이동, 회전, 보관, 상태 읽기, 표면 스캔, 하드 드롭 호출 통과
- 블록 퍼즐 시작, 이동, 회전, 선택, 배치 호출 통과
- 음성/효과음/BGM/잠금 유예 설정 전환 통과
- 반복 하드 드롭 스트레스 호출에서 예외 없음
- `window.getPortraitFrame()`: 60행 × 40열
- `window.getDotpadFrame()`: 600 hex 문자 = 300 bytes
- `window.getAccessibilityState()` 진단 API 제공
- HTML ID 100개 중복 없음, 핵심 스크립트 참조 ID 누락 없음
- 절차형 오디오 엔진을 모의 AudioContext에서 전체 이어콘 호출 검증


## 화면 분리 및 반응형 검증

- Chromium 기반 Playwright UI 시뮬레이션에서 인트로 → 플레이 → 설정 → 일시정지 → 계속 → 인트로 흐름 통과
- 데스크톱 1440×900: 인트로, 낙하 플레이, 설정 서랍 렌더링 확인
- 모바일 390×844: 인트로, 블록 퍼즐 플레이와 3개 퍼즐 트레이 렌더링 확인
- `window.getDotpadFrame()` 600 hex와 `getAccessibilityState().frameLength` 600 유지
- 실행 중 JavaScript page error 및 console error 없음
- 기본 블록은 Canvas, 배경은 WebP, 특수 아이템은 투명 SVG로 역할 분리

## 실제 DotPad에서 반드시 확인할 항목

이 실행 환경에는 DotPad BLE 하드웨어가 없으므로 아래 항목은 실제 사용자 테스트가 필요합니다.

1. `cw`와 `ccw` 중 실제 세로 거치 방향과 일치하는 기본값
2. 고정 블록/현재 블록/예상 착지 세 질감의 구별 가능성
3. 4×3핀 셀에서 현재 블록 테두리가 손끝에 충분히 명확한지
4. 표면 스캔이 10개 열 높이를 빠르게 이해하는 데 도움이 되는지
5. 상단 위험 경고점이 게임 블록으로 오인되지 않는지
6. F1+F2, F3+F4, RPF4 동시/보조 키 코드가 기기 펌웨어별로 일치하는지
7. BLE 갱신 중 빠른 좌우 이동에서 프레임 누락이 없는지
8. 음성 안내가 재생되는 동안 음악 감쇠가 충분한지
9. 이어폰 사용 시 좌우 방향 효과음이 명확한지
10. 실제 시각장애인 사용자 3명 이상이 화면 없이 10분 이상 플레이 가능한지

## 권장 사용자 테스트 과업

### 낙하 모드

- I 블록을 왼쪽 끝과 오른쪽 끝까지 이동
- 블록을 2회 회전하고 예상 착지 위치 확인
- 블록 보관 후 다른 블록과 교체
- 표면 스캔으로 가장 높은 열 찾기
- 한 줄 완성 후 줄 삭제 피드백 설명
- 위험 경고 후 높이를 낮추기

### 블록 퍼즐

- 3개 블록을 차례로 선택
- 겹치는 자리의 X 질감 찾기
- 가로줄과 세로줄 각각 1회 삭제
- 상세 상태 읽기로 가장 많이 찬 행 찾기

## 합격 기준 제안

- 조작 성공률 90% 이상
- 현재 블록/고정 블록/착지 표시 구분 정확도 85% 이상
- 도움 없이 첫 줄 삭제까지 8분 이내
- 상태 읽기 요청 후 현재 열 범위 응답 정확도 90% 이상
- 게임 종료 이유를 모든 참가자가 설명 가능
